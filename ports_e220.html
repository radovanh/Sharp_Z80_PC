PC-E220 I/O Port Reference

Complete Z80 I/O port map for the Sharp PC-E220 (1991). The LCD is 120 × 32 pixels split into two 60-column halves (HD62202 left, HD61203 right). Pixel plotting uses HD61203-style page-select commands ($B8|N) at port $58, requires a ROM busy-wait call at $8530 after every port access, and must compensate for BIOS scroll drift using the live offset byte at RAM address $790D. Data from Achim Flammenkamp (uni-bielefeld.de) and direct analysis of the hardware-verified plot_e220.asm pixel library.

LCD Port Map PC-E220

ARCHITECTURE: The E220 LCD is 120 x 32 pixels split at X=60. Both halves share port $58 (command) and $5A/$5B (data). The active half is selected by the N value in the page-select command. After every OUT or IN to an LCD port, call the ROM busy-wait routine at $8530.
PORTDIRNAMEDESCRIPTION
$58 OUT LCD command Page-select: $B8 | ((N + PAGE_COMPENS) & $07)
Column-select: $40 | colpos Send page command first, then column command. Both via this port. Call $8530 busy-wait after each.
$59 IN LCD busy flag Bit 7 = 1 means LCD controller busy. Do not poll manually — call LCD_BUSY_WAIT at $8530 instead.
$5A OUT LCD data write Write one pixel byte (8 vertical pixels) at current cursor. Column auto-increments after write. Bit 0 = topmost pixel. Bit 7 is non-visible on this display — writing it has no effect on screen.
$5B IN LCD data read Read pixel byte at current cursor. First read after a page/column seek is stale — always read twice (dummy + real). Read also auto-increments the column pointer. Must re-issue page+column commands before the subsequent write (see RMW section).
BUSY-WAIT REQUIRED AFTER EVERY ACCESS: Unlike the G850, the E220 LCD controllers require a busy-wait after every OUT $58, OUT $5A, and IN $5B. Call the ROM routine LCD_BUSY_WAIT EQU $8530 every time. Skipping any call produces corrupt or missing pixels.

Display Geometry 120 x 32 NOT 144

120 COLUMNS, NOT 144: The E220 display is 120 pixels wide (X = 0–119). Code ported from the G815 or G850 must clip or rescale X coordinates. The right half is addressed right-to-left: colpos = 119 − X for X ≥ 60.
LOGICAL XCONTROLLERcolpos FORMULAside (for N_TABLE)
0 – 59 Left — HD62202 colpos = X 0 → side*4 = 0
60 – 119 Right — HD61203 (RTL) colpos = 119 − X 1 → side*4 = 4

The column address command is always OUT($58, $40 | colpos) with colpos in range 0–59. Which physical controller responds is determined by the N value in the preceding page-select command, not by the colpos value itself. 

  ; Compute side*4 and colpos from D=X (0-119)
  get_side_col:     ; returns B=side*4, C=colpos
      ld   a, d
      cp   60
      jr   c, gsc_left
      ; right half: colpos = 119 - X, side*4 = 4
      ld   a, 119 \ sub d \ ld c, a
      ld   b, 4
      ret
  gsc_left:
      ld   c, d           ; colpos = X
      ld   b, 0           ; side*4 = 0
      ret

Page Command — $B8|N Encoding

TWO DIFFERENT ENCODINGS ON PORT $58: The BIOS text-output routines use a packed (col*4)+row|$40 byte for the text cursor. Direct pixel plotting uses the HD61203 page-select format $B8|N. These are distinct encodings on the same port, used in different contexts. The pixel library always uses $B8|N.

The page command selects both the 8-pixel row band and the active controller half. N is not simply Y >> 3 — it must be looked up from N_TABLE using side*4 + row, then compensated with the PAGE_COMPENS byte before sending.

N_TABLE — Side and Row Lookup

An 8-byte table in program data. Index = side*4 + row, where side = 0 (X<60) or 1 (X≥60), and row = Y >> 3 (0–3).

  N_TABLE:
      db 0,1,2,3    ; side=0 (left,  X 0-59),   rows 0-3
      db 4,5,6,7    ; side=1 (right, X 60-119), rows 0-3

  ; Look up N: B=side*4 (0 or 4), E=Y
  lookup_N:
      ld   a, e
      rrca \ rrca \ rrca  ; A = Y >> 3 = row (0-3)
      and  $07
      add  a, b           ; index = side*4 + row
      ld   hl, N_TABLE
      add  a, l \ ld l, a
      jr   nc, ln_nc \ inc h
  ln_nc:
      ld   a, (hl)        ; A = N (0-7)
      ret

PAGE_COMPENS — Drift Compensation RAM $790D

WHY THIS EXISTS: BIOS text-scroll routines advance an internal scroll register in the LCD controllers as text rows scroll up. This shifts which physical page the hardware considers "page 0", causing direct pixel writes to land on the wrong rows after any scroll has occurred. The BIOS tracks this drift in a live byte at RAM address $790D.

Before sending any page-select command, read the byte at $790D, add it to the raw N value from N_TABLE, mask to 3 bits (wrapping within the 8-page ring), then OR with $B8. 

  PAGE_COMPENS  EQU  $790D   ; BIOS work area: live scroll-drift offset

  ; Apply compensation and send page-select command
  ; Input: A = raw N from N_TABLE (0-7)
  send_page_cmd:
      ld   hl, PAGE_COMPENS
      add  a, (hl)      ; N + live scroll offset
      and  $07          ; wrap to 3 bits (ring of 8 pages)
      or   $B8          ; HD61203 page-select command class
      out  ($58), a
      call $8530        ; LCD_BUSY_WAIT
      ret

  ; Send column-select command (always after page command)
  ; Input: C = colpos (0-59)
  send_col_cmd:
      ld   a, $40 \ or c
      out  ($58), a
      call $8530
      ret
ALTERNATIVE — RESET AT PROGRAM START: Issue OUT($58, $B8) once at startup to force scroll to line 0, then avoid all BIOS text calls that could scroll the display. Safe for self-contained ML programs that own the entire screen. The compensation approach via $790D is needed when BASIC text output is interleaved with direct graphics.

Pixel Byte Format BIT 7 INVISIBLE

BIT 7 DOES NOT PRODUCE A VISIBLE PIXEL: Each byte controls 8 vertical pixels, but bit 7 maps to a non-printable row in the E220 LCD panel. The effective visible range per page band is bits 0–6 (7 pixels), giving a true visible height of 28 pixels across 4 pages, even though Y accepts values 0–30. Y values 7, 15, 23, and 31 map to bit 7 and produce no visible pixel. 
  One byte = 8 vertical pixels at the current column:

  Byte:   bit7     bit6  bit5  bit4  bit3  bit2  bit1  bit0
  Row:  [INVIS]   Y+6   Y+5   Y+4   Y+3   Y+2   Y+1   Y+0  <-- topmost

  Bit 7 is transmitted but produces no visible pixel on E220 hardware.
  Affected Y values (Y mod 8 == 7): Y = 7, 15, 23, 31.

  bit_index = Y & $07       ; 0-7 (7 is invisible)
  mask      = 1 << bit_index
  page      = Y >> 3        ; 0-3

  Effective coordinate range for visible pixels: X 0-119, Y 0-30
  Visible pixel rows per page: 7 (bits 0-6 only)
  Total visible pixels vertically: 28

Read-Modify-Write Protocol

Setting or clearing a single pixel requires reading the existing byte at that column, modifying one bit, and writing it back. Three E220-specific complications apply:

  1. 1 Dummy read required. The first IN A,($5B) after a page+column seek returns stale latched data. Always read twice — discard the first result, use the second.
  2. 2 Read auto-increments the column pointer. After both reads the internal column counter has advanced by two. You must re-issue the full page-select + column-select sequence before the write, or the data will land on the wrong column.
  3. 3 Busy-wait after every port access. Call $8530 after the dummy read, after the real read, after each command of the re-issue sequence, and after the final write if further LCD access follows immediately. 
  ; Read-modify-write skeleton (page+col already selected via PB_ADDR)
  ; C = bit_index (0-7) saved from PB_ADDR return value

      ; step 1 -- dummy read (stale latch after seek)
      in   a, ($5B)
      call $8530

      ; step 2 -- real read: existing pixel byte
      in   a, ($5B)
      ld   b, a           ; B = existing byte
      call $8530

      ; step 3 -- re-select page+col (reads advanced column pointer by 2)
      push bc
      call PB_ADDR        ; re-issues page and column commands with busy-waits
      pop  bc             ; restore C=bit_index, B=existing byte

      ; step 4 -- compute mask and merge
      ld   h, c \ ld a, 1 \ inc h
  shift:
      dec  h \ jr z, done \ sla a \ jr shift
  done:
      or   b              ; OR to set pixel  (use CPL/AND B to clear)

      ; step 5 -- write back
      out  ($5A), a
CLEARING A PIXEL: Replace OR B with CPL then AND B. CPL inverts the mask so only the target bit is 0 while all others remain 1; the subsequent AND with the existing byte clears only that bit.

LCD Busy-Wait ROM $8530

LCD_BUSY_WAIT EQU $8530 — ROM routine. Polls port $59 bit 7 in a tight loop until the LCD controller signals ready, then returns. Must be called after every OUT($58,...), OUT($5A,...), and IN A,($5B). This is the key difference from the G850 which tolerates back-to-back port writes without waiting. 
  LCD_BUSY_WAIT  EQU  $8530   ; ROM busy-wait; call after every LCD port access
  LCD_CMD_PORT   EQU  $58     ; command port (page-select and column-select)
  LCD_DATA_OUT   EQU  $5A     ; pixel data write
  LCD_DATA_IN    EQU  $5B     ; pixel data read (first read after seek is stale)
  PAGE_COMPENS   EQU  $790D   ; RAM: live page-drift offset (add to N before $B8|N)

  ; Equivalent inline logic (the ROM routine does this):
  busy_inline:
      in   a, ($59)
      bit  7, a
      jr   nz, busy_inline
      ret

Full Command Sequence — Setting One Pixel

  1. 1 Bounds check. X must be 0–119, Y must be 0–30. Y mod 8 == 7 (values 7, 15, 23, 31) maps to invisible bit 7 — the write succeeds but nothing appears on screen.
  2. 2 Compute side and colpos. X < 60: side=0, colpos=X. X ≥ 60: side=1, colpos=119−X.
  3. 3 Compute row and bit_index. row = Y >> 3. bit_index = Y & $07. mask = 1 << bit_index.
  4. 4 Look up N. index = side*4 + row. N = N_TABLE[index].
  5. 5 Read PAGE_COMPENS and compute page command. page_cmd = ($B8 | ((N + MEM[$790D]) & $07)).
  6. 6 Send page command. OUT($58, page_cmd) → CALL $8530.
  7. 7 Send column command. OUT($58, $40 | colpos) → CALL $8530.
  8. 8 Dummy read. IN A,($5B) → CALL $8530. Discard result.
  9. 9 Real read. IN A,($5B) → CALL $8530. Save in register B.
  10. 10 Re-issue page+column (steps 6–7). The two reads advanced the column pointer by two. Reset it.
  11. 11 Merge and write. A = B | mask (set pixel) or A = B & ~mask (clear pixel). OUT($5A, A).

PB_ADDR + PLOT_PIXEL + PLOT_PIXEL_CLR

From the hardware-verified plot_e220.asm pixel library. D = X (0–119), E = Y (0–30). Origin top-left. 

  ; ── ROM/RAM constants ────────────────────────────────────────
  LCD_BUSY_WAIT EQU $8530   ; ROM: poll $59 bit7, loop until clear
  PAGE_COMPENS  EQU $790D   ; RAM: live page-drift offset byte

  ; ── N_TABLE (8 bytes in program data) ───────────────────────
  N_TABLE:
      db 0,1,2,3    ; side=0 (left  X 0-59)   rows 0-3
      db 4,5,6,7    ; side=1 (right X 60-119) rows 0-3

  ; ── PB_ADDR ──────────────────────────────────────────────────
  ; Select LCD page+column for pixel at D=X, E=Y.
  ; Returns: A = bit_index (Y mod 8). Page+col commands already sent.
  ; Destroys: B, C, H, L
  PB_ADDR:
      ; --- side + colpos from X ---
      ld   a, d \ cp 60
      jr   c, PBA_LEFT
      ld   a, 119 \ sub d \ ld c, a   ; right: colpos=119-X
      ld   b, 4                        ; side*4=4
      jr   PBA_SIDE
  PBA_LEFT:
      ld   c, d \ ld b, 0             ; left: colpos=X, side*4=0

  PBA_SIDE:
      ; save bit_index = Y mod 8
      ld   a, e \ and $07
      push af

      ; row = Y >> 3, look up N from N_TABLE
      ld   a, e
      rrca \ rrca \ rrca \ and $07    ; A = row (0-3)
      add  a, b                        ; index = side*4 + row
      ld   hl, N_TABLE
      add  a, l \ ld l, a
      jr   nc, PBA_NC \ inc h
  PBA_NC:
      ld   a, (hl)                     ; A = N (0-7)

      ; apply PAGE_COMPENS: compensate for BIOS scroll drift
      ld   hl, PAGE_COMPENS
      add  a, (hl)
      and  $07                         ; wrap in 8-page ring
      or   $B8                         ; page-select command
      out  ($58), a
      call LCD_BUSY_WAIT

      ; column-select command
      ld   a, $40 \ or c
      out  ($58), a
      call LCD_BUSY_WAIT

      pop  af                          ; A = bit_index
      ret

  ; ── PLOT_PIXEL ───────────────────────────────────────────────
  ; Set pixel at D=X (0-119), E=Y (0-30).
  ; Note: Y mod 8 == 7 writes bit 7 which is invisible on E220.
  ; Destroys: A, B, C, H, L
  PLOT_PIXEL:
      call PB_ADDR          ; A=bit_index, page+col selected
      ld   c, a

      in   a, ($5B)          ; dummy read (stale after seek)
      call LCD_BUSY_WAIT

      in   a, ($5B)          ; real read: existing byte
      ld   b, a
      call LCD_BUSY_WAIT

      push bc
      call PB_ADDR          ; re-select: reads advanced column pointer
      pop  bc                ; C=bit_index, B=existing byte

      ld   h, c \ ld a, 1 \ inc h
  PP_SHIFT:
      dec  h \ jr z, PP_DONE \ sla a \ jr PP_SHIFT
  PP_DONE:
      or   b                 ; set pixel bit
      out  ($5A), a
      ret

  ; ── PLOT_PIXEL_CLR ───────────────────────────────────────────
  ; Clear pixel at D=X (0-119), E=Y (0-30).
  ; Destroys: A, B, C, H, L
  PLOT_PIXEL_CLR:
      call PB_ADDR
      ld   c, a

      in   a, ($5B)          ; dummy read
      call LCD_BUSY_WAIT

      in   a, ($5B)          ; real read
      ld   b, a
      call LCD_BUSY_WAIT

      push bc
      call PB_ADDR          ; re-select column
      pop  bc

      ld   h, c \ ld a, 1 \ inc h
  PPC_SHIFT:
      dec  h \ jr z, PPC_DONE \ sla a \ jr PPC_SHIFT
  PPC_DONE:
      cpl                    ; invert mask: target bit=0, others=1
      and  b                 ; clear only the pixel bit
      out  ($5A), a
      ret

  ; ── PLOT_BYTE ────────────────────────────────────────────────
  ; Write a full byte B at column D=X, page of E=Y. No RMW.
  ; Destroys: A, B, C, H, L
  PLOT_BYTE:
      push bc
      call PB_ADDR
      pop  bc
      ld   a, b
      out  ($5A), a
      ret

Keyboard Ports $10 – $13

PORTDIRNAMEDESCRIPTION
$10IN Column read Bitmask of currently strobed row. Bit=1 means key pressed (active-high). Read after writing strobe to $11 or $12.
$11OUT 8x8 row strobe 1-bit mask selects one of 8 main matrix rows ($01–$80). Write 0 to deselect.
$12OUT Function key strobe Bit 0 = fn row 0, bit 1 = fn row 1. Read result from $10.
$13IN SHIFT key Bit 0 = SHIFT pressed (1=pressed). Independent of matrix scan. 
  ; Scan main matrix. Returns A=col bits, B=row bit if key found; A=0 if none.
  scan_keys:
      ld   b, $80
  sk_row:
      ld   a, b \ out ($11), a
      in   a, ($10) \ or a
      ret  nz           ; key found: A=col mask, B=row mask
      rrc  b \ jr nc, sk_row
      xor  a \ ret      ; no key pressed

Interrupt Ports $16 / $17

PORTDIRBITSDESCRIPTION
$16I/O bits 0–3 Read: pending interrupt flags. Write: clear flags. Bit 0=keyboard · Bit 1=ON key · Bit 2=timer (~0.95 s LCD clock) · Bit 3=CPU INT pin
$17OUT bits 0–3 Enable/disable interrupt sources (1=enabled). Same bit mapping as $16.
$14I/O bit 0 LCD driver oscillator divided-down timer signal. Period ~0.95 s. Not a GP timer.

ROM Bank Mapping PORT $19

8 x 16 KB BANKS: Port $19 bits 0–2 select one of 8 internal ROM banks into the $C000–$FFFF window. Bank 0 (BIOS) is always mapped at $8000–$BFFF. Current bank value is mirrored at RAM $7900h.

Serial Interface Ports $15 / $18 / $1F

PORTDIRBITSDESCRIPTION
$15I/Obit 0, 7 Bit 0: clear to enable XIN input. Bit 7: XIN enabled/inhibited.
$18I/Obits 0,1,7 Bit 0=BUSY/CTS (pin 4) · Bit 1=DOUT (pin 5) · Bit 7=XOUT/TXD complement (pin 7). Bit 7 is serial TX data — write the complement of each bit.
$1FINbits 0,1,2,7 Bit 0=DIN (pin 8) · Bit 1=ACK/RTS (pin 9) · Bit 2=XIN/RXD complement (pin 6) · Bit 7=ON/break key. XIN data is inverted — complement bit 2 to get the received data bit.
PROTOCOL: Intel Hex format, up to 9600 baud, 0 V/5 V CMOS logic. RS-232 level converter required for PC interfacing. Allow ≥ 0.1 s pause after each Intel Hex line for the Sharp to decode and verify.
