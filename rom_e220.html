PC-E220 ROM / BIOS Reference

System ROM entry points, work area map, key code table, software limits, and RAM layout for the Sharp PC-E220 (1991). Many BIOS addresses are shared with the G815/G850 series — entries marked E220 are E220-specific or have a different address/behaviour. Sources: Achim Flammenkamp's technical analysis (uni-bielefeld.de), including ROM entry point list and RAM usage map.

REGISTER CONVENTIONS: Character position: D = row (0–3), E = column (0–23). For graphics (BFD0h): D = character column (0–23), E = row (0–3). The E220's BIOS call interface is largely identical to the G815/G850 — code written for the G815 will often run unmodified.

Display Routines

BE62h
Single Character Output
DISPLAY
// INPUT
A = ASCII character
D = row (0–3)
E = column (0–23)
// OUTPUT
None
// DESTROYS
AF BC HL
Outputs one ASCII character at position (D, E). Address is identical to G815/G850.
BFEEh
Repeated Character Output
DISPLAY
// INPUT
A = ASCII character
B = repeat count
D = row (0–3)
E = column (0–23)
// OUTPUT
C = scroll count
DE = position after last char
// DESTROYS
AF B HL
Outputs the same character B times starting at (D, E). To clear the screen: LD A,0x20 / LD B,96 / LD DE,0 / CALL BFEEh (96 = 4 rows × 24 columns).
BFF1h
String Output
DISPLAY
// INPUT
B = byte count
D = row (0–3)
E = column (0–23)
HL = string address
// OUTPUT
C = scroll count
DE = position after last
HL = address after last byte
// DESTROYS
AF B
Outputs B bytes from HL starting at (D, E). String is raw ASCII, not null-terminated. Wraps to next row and scrolls if the string exceeds column 23.

Graphics / Pattern Output

BFD0h
Graphics Pattern Output (GPRINT)
DISPLAY
// INPUT
B = byte count
D = char column (0–23)
E = row (0–3)
HL = pattern data address
// OUTPUT
HL = address after last byte read
// DESTROYS
AF B DE HL
Outputs B pixel bytes from HL at character column D, row E. Each byte = 8 vertical pixels (bit 0 = topmost). The BIOS handles LCD port writes internally using port 58h/5Ah. Granularity is one character column (6 pixels) — sub-character pixel addressing requires direct port access.
BFD0h destroys DE and HL. Always save them: PUSH DE / PUSH HL / CALL BFD0h / POP HL / POP DE. Address is identical to G815/G850.
E220 vs G815 GPRINT DIFFERENCE: On the G815, BFD0h uses D as a pixel column (0–143). On the E220, D is a character column (0–23). This is because the E220 LCD controller only accepts character-column granularity natively. If porting G815 code that uses pixel-exact X coordinates, convert: char_col = pixel_x / 6.

Clear Screen Routines

BFEBh
Clear Graphics Screen
DISPLAY
// INPUT
None
// OUTPUT
None
// DESTROYS
AF B HL
IX undefined after call
Clears the entire 144×32 pixel display (equivalent to BASIC CLG). Zeros all pixel data via port 5Ah.
BE65h
Clear to End of Line
DISPLAY
// INPUT
D = row (0–3)
E = column (0–23)
// OUTPUT
None
// DESTROYS
AF BC DE HL
Clears from (D, E) to the end of that row.
  ; Full clear sequence for ML programs:
  cls_full:
      ld   a, 020h     ; space character
      ld   b, 096h     ; 4 rows × 24 cols = 96
      ld   de, 0000h  ; row 0, col 0
      call 0BFEEh      ; fill with spaces (text layer)
      call 0BFEBh      ; clear graphics layer
      ret

Input Routines

BE53h
Get Key Code (No Wait)
INPUT
// INPUT
None (interrupts must be enabled)
// OUTPUT
A = key code (0 = no key)
Cy = 1 if key pressed
// DESTROYS
F
Returns immediately. If no key pressed, A = 0 and carry is clear. Returns key code from the IOCS table below. Requires EI to be active.
Polling loop: CALL BE53h / OR A / JR Z, loop. Address shared with G815/G850.
BCFDh
Wait for Key Press
INPUT
// INPUT
None
// OUTPUT
A = key code
// DESTROYS
F
Blocks until a key is pressed, then returns its key code in A. Equivalent to BASIC's INKEY$ with a built-in wait loop.
BE56h
Key Code → ASCII Character
INPUT
// INPUT
A = key code (from BE53h)
// OUTPUT
A = ASCII character
// DESTROYS
F B
Converts a raw IOCS key code to the corresponding ASCII character, respecting CAPS lock state.
BD09h
Input 2-Digit Hex Value
INPUT
// INPUT
None
// OUTPUT
A = 8-bit hex value
// DESTROYS
F BC DE HL IX IY
Waits for the user to type two hex digits (e.g. "4F") and returns the byte value in A.
BD0Fh
Input 4-Digit Hex Value
INPUT
// INPUT
None
// OUTPUT
HL = 16-bit value
// DESTROYS
A BC DE IX IY
Waits for the user to type four hex digits and returns the 16-bit word in HL.

System Routines

C110h
Power Off
SYSTEM
// INPUT
None
// OUTPUT
Does not return
// DESTROYS
N/A
Shuts the unit off. Resumes from BASIC prompt when the ON key is pressed. Address shared with G815/G850.
0030h
Register Dump (RST 30h)
SYSTEM
// INPUT
None
// OUTPUT
Displays on screen
// DESTROYS
None
Invoked via RST 30h (opcode 0xF7). Displays all CPU register values on screen for debugging. Returns to MON rather than caller.

Memory Map Z80 ADDRESS SPACE

ADDRESS RANGESIZECONTENT
0000h–00FFh256 BZ80 vectors / system — interrupt table, RST vectors. Not user RAM.
0100h–77E0h~30 KBUser RAM — 30,090 bytes free for BASIC programs and ML code
77E1h–7FFFh~2 KBSystem work area — BIOS variables, key buffer, scroll offset, bank register mirror (see below)
8000h–BFFFh16 KBROM bank 0 (BIOS) — always mapped, contains system routines and IOCS table
C000h–FFFFh16 KBROM switchable window — bank 1 (BASIC) by default; selectable via port 19h
USER CODE ORG: ML programs loaded via the assembler module should use ORG 0100h as the start address, matching the base of user RAM. The ROM entry points (BE53h, BFD0h, etc.) are always accessible in the 8000h–BFFFh window regardless of which bank is selected at C000h–FFFFh. 
  ; Typical ML program header for PC-E220
      org  0100h      ; base of user RAM

  start:
      ld   (saved_sp), sp   ; save SP so we can return cleanly
      ; ... your code here ...

  exit:
      ld   sp, (saved_sp)
      ret                    ; return to MON / BASIC

  saved_sp:
      dw   0

System Work Area RAM 7800h–7FFFh

ADDRESSNAMEDESCRIPTION
779ChContrastLCD contrast value. Write to hardware is via direct port write; this mirrors the current setting.
7900hROM bank (C000–FFFF)Mirror of current value written to port 19h bits 0–2. Read to determine active bank.
7901hCAPS/Kana lockBit 0 = always 1. Bit 1 = CAPS lock. Bit 2 = Kana lock. Writable.
790DhVRAM scroll startLower 4 bits × 8 = pixel scroll offset used by BIOS text scroll. Read to compensate Y in ML graphics.

DIAGNOSTIC MODE: Hold SHIFT + , (colon) while pressing RESET to enter the diagnostic menu. Five diagnostic modes are selectable — caution: the RAM Check mode clears all memory. The ROM version (V.0, V.1, or V.2) is displayed in this mode.

G815 vs E220 — Key Differences

The G815 and E220 share the same BIOS call addresses and most register conventions, but differ importantly in LCD port assignment, command encoding, and CPU speed.

FEATURE PC-G815 PC-E220
CPU Z80 CMOS 8 MHz SC7852 (Z80A compat) 3.58 MHz
Not cycle-compatible — timing loops need adjustment
LCD resolution 144 × 32 px (4 pages) 144 × 32 px (4 pages) — identical
LCD controllers 2 × HD61203 HD62202 + HD61203
LCD command port 54h (left) / 58h (right) 58h only — single command port
LCD data port 56h / 5Ah 5Ah only
Command encoding Page (0xB8+p) then column (0x40+col) as separate bytes Single byte: (char_col × 4) + row | 0x40
X granularity in BIOS BFD0h uses pixel column D (0–143) BFD0h uses character column D (0–23)
Busy port 55h (left) / 59h (right) 59h — bit 7 = busy
Keyboard matrix OUT(11h,row) / IN(10h) OUT(11h,row) / IN(10h) + OUT(12h,row) for fn keys
ROM banking None (single 128 KB ROM, bank 0 always visible) 8 × 16 KB banks via port 19h
User RAM 32 KB (model dependent) ~30 KB (0100h–77E0h)
BIOS call addresses BE53h / BCFDh / BFD0h / BFEEh / BFF1h / C110h … Identical for all shared routines
Serial interface CE-140F disk / serial via 11-pin SIO 9600 baud Intel Hex via 11-pin (ports 15h/18h/1Fh)
PORTING CHECKLIST (G815 → E220): Change LCD command port from 54h/58h to 58h only · Change LCD data port from 56h/5Ah to 5Ah only · Change command encoding from separate page + column to packed single byte · Adjust timing loops for 3.58 MHz (roughly halve loop counts vs 8 MHz G815) · BIOS call addresses (BFD0h etc.) remain unchanged · If using BFD0h, note that D is now a character column (0–23), not a pixel column.
